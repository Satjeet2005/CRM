# ForgeFlow-to-Sakani Screen Mapping

This document establishes the screen-by-screen architectural crosswalk mapping existing **ForgeFlow** routes and workflows to **Sakani CRM** layouts, components, blocks, and design tokens.

---

## 1. Classification Categories

- **A — Direct reuse**: Existing Sakani component or block can be reused with little to no adaptation.
- **B — Compose**: Build the ForgeFlow screen by combining existing Sakani layouts, blocks, and reusable components.
- **C — Adapt**: Use a related Sakani screen or component as the foundation but make deliberate adjustments for ForgeFlow's domain requirements.
- **D — New design required**: No suitable Sakani pattern exists; a ForgeFlow-specific interface must be constructed from Sakani tokens.
- **E — Preserve**: Keep the current ForgeFlow implementation because replacement provides minimal benefit or presents high regression risk.

## 3. Summary of Category Distributions

- **A — Direct reuse**: **0** (No screen can be copied verbatim because ForgeFlow's screens require specialized manufacturing data models, Decimal currency, and RBAC permissions).
- **B — Compose**: **10 screens (62.5%)** (Dashboard, Accounts, Account Detail, Contacts, Opportunity Detail, Tasks, RFQs, Quotes, Activity, Shell).
- **C — Adapt**: **4 screens (25.0%)** (Login, Opportunities Pipeline, Catalog, RFQ Import Wizard).
- **D — New design required**: **2 screens (12.5%)** (RFQ Review Studio Candidate Match Drawer & Quotation Studio Calculation Trace / Diff Inspector — both composed from Sakani tokens).
- **E — Preserve**: **0 screens** entirely preserved, but **all underlying API services, TanStack Query hooks, form validation logic, and calculation math are 100% preserved**.
